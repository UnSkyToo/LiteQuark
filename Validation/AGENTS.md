# Validation 维护规则

适用于本目录及子目录。运行、覆盖范围和报告语义见 [README.txt](README.txt)。

## 场景与归属

- 从使用者可观察的结果确定场景。同一业务时间线可有多个断言，优先复用真实输入、资源和时序。廉价的输入差异可参数化。保留与故障机制相应的失败定位。
- 修改所属 suite 的强类型登记和方法。Core 管理路径、任务、Runtime 和核心对象池，Asset 管理收集、打包、寻址与生命周期，Addons 管理扩展模块及真实 UI 重启链。按模块放置专用探针，删除场景时清理仅由它使用的夹具。
- Sources 是维护源码。优先使用公开入口和普通 C# 类型，原生时序观察和跨 Assembly-CSharp 的真实集成可保留有明确用途的窄适配。不要通过篡改生产缓存或检查旧方法名缺席来制造场景。
- 两个平台都使用 Scenarios.json，与 C# 登记独立。场景增删时一起修改对应 suite 的清单及实现，保留既有 ID 的含义。每个场景报告 ID、结果、检查数、失败、耗时与证据。清理期间的错误也由当前场景承担。
- 保留 UNITY-SAME-NAME-SCENE-BUNDLES 及其独立诊断的精确触发条件。日常通过数排除以上两项；额外错误、未确认诊断和夹具代为清除的泄漏均应失败。

## 同步与隔离

- 对当前工作区运行，Unity 版本、依赖声明和锁定版本取自主工程。隔离 Editor asmdef 只在生成副本增加 UniTask、LitJson、LiteQuark.Runtime.Addons 引用。
- 保持 Windows PowerShell 与 macOS 系统 Bash 入口的同步、报告校验和退出条件一致。macOS 只使用系统依赖。平台专属断言依据宿主能力，测试字符串按其本意保留。
- 递归同步 Sources，保留已有文件及目录的 Unity GUID，新项带相应 .meta。写入和递归清理前检查绝对路径及链接，包括失效链接。维护运行锁、过期副本清理、代码路径集合及指纹，检测到外部修改时保留证据。
- 缓存、报告、Bundle 与锁文件不入库。不读取或清理旧 LiteQuark/SessionValidation 缓存及历史报告。

## 验证

- 通过原生入口编译和运行受影响 suite。共享设施、清单判定或退出条件变化时运行全量。
- 同步流程变化时验证空生成目录重建和再次运行。隔离检查应发现 asmdef 链接、目录链接与失效 .meta 链接，在写入前中止并保全目标；运行中新增、修改、删除隔离代码或其 .meta 必须使验证失败。
- 报告入口应拒绝漏注册、重复和意外 ID，以及缺席或错分的限制诊断。对场景精简说明保留的公开边界及删去的夹具。交付真实平台、范围、数量、限制、诊断和隔离证据。
- 文档改动核对本地引用、字段语义和空白；未跟踪文件也须检查。
