# Validation 维护规则

适用于本目录及子目录。运行方法、目录、覆盖范围及报告语义只维护在 [README.txt](README.txt)；这里规定如何修改验证代码。

## 源码与入口

- Sources 是唯一维护源码；Project 是生成副本。不要直接修改隔离副本。
- Windows 使用 Run-Validation.ps1，macOS 使用 Run-Validation.sh；后者只依赖系统工具，不要求安装 PowerShell 或其他脚本运行时。两份入口保持相同的模块、通过条件、已知限制及隔离检查，不再增加平台外的通用调度框架。
- 沿用现有模块及共享设施，不新增按提交、日期或实验命名的 Runner/工程，不引入通用执行框架。临时实验放 Scratch，完成后清理。
- lifecycle 保持同一个 static partial 类：原文件负责启动、注册、报告和清理，.Assets、.Scenes、.Scheduling 放相应用例，.Fixtures 放资源生成及辅助对象。文件直接放 Sources 下，保持入口、名称和注册顺序；新增文件补 .meta，已有 GUID 不变。
- 历史缺陷维护为当前实现的输入和预期，不保留旧实现或候选修复副本；旧格式只使用固定测试数据。

## 正确性与隔离

- 验证当前工作区，包括未提交修改；依赖及 Unity 版本取自主工程，不维护第二套清单，不顺带升级。
- 不修改主工程、暂存区或隔离生产代码来获得通过。唯一程序集适配仍为隔离 Editor asmdef 补 UniTask、LitJson 引用。
- 不降低断言、跳过失败或新增豁免。预期错误随用例声明，作用域包括清理，不按显示编号/名称忽略日志。
- 严格保留 README 中已知限制的独立诊断条件与分类；日常回归、限制和诊断分开统计，清理泄漏和未确认诊断仍失败。
- 保留运行锁、过期副本清理及运行前后指纹检查；发现外部修改时保留修改，不回滚他人工作或绕过检查。
- 平台适配只处理实际的宿主差异；固定路径/URI 测试数据不可当作环境硬编码批量改写。Bundle 使用本机平台；没有实机证据时不宣称该平台通过。
- 缓存、报告、Bundle 和运行锁不入库。递归清理须先验证绝对路径和目录链接，不越出生成目录；旧 LiteQuark/SessionValidation 缓存和历史报告按用户要求保留，不读取、覆盖或清理。

## 验证与交付

- 源码改动通过统一入口编译并验证受影响模块；公共执行、分类或退出码变化时全量验证。初始化/同步改动还要验证空生成目录重建和重复运行。
- 隔离检查改动须验证：asmdef 文件链接、目录链接和失效 .meta 链接在写入前被拒绝，链接目标不变；运行期间隔离代码的新增、修改、删除均使结果失败。
- 重构逐项对照用例名称、顺序、结果及分类；删去重复/无效断言时说明每项断言数变化和保留覆盖的位置。用例增减同步两份入口的预期数，覆盖范围变化时更新 README；入口分类改动须检查两端一致，不能为了原生脚本省略检查。
- 文档改动检查本地链接、字段语义与 git diff --check，不必启动 Unity；未跟踪文件也要检查空白。
- 交付实际执行平台、范围、通过数、限制、诊断和隔离结果，链接报告并说明未运行的检查，不把历史或其他平台结果当成本次通过。
